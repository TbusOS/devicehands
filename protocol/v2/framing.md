# v2 线路格式:WebSocket 消息、job 帧、字节流通道、参数规则

本文是 v2 的规定,两个实现(Python、以后的 Rust)都按它做。和 v1 的差别见
[DESIGN.md](DESIGN.md) 第 3 节;v1 的现状描述留在 [`../v1/`](../v1/) 作历史。
顺序和时间(谁先谁后、等多久)在 [sequences.md](sequences.md)。

## 1. 两类连接,四种用途

```
 台架                                          主程序(hub)
 ────                                          ───────────
 信令连接  ws(s)://<hub>/bench/connect  ───▶   JSON 文本消息,一条消息 = 一个控制帧
           头 x-dhands-token
 数据连接  ws(s)://<hub>/bench/channel?cid=…   一个 open_channel 对应一条
           头 x-dhands-token、x-dhands-csecret
   ├ tcp     (adb)    二进制消息 = 原始字节流
   ├ serial  (串口)   二进制消息 = 原始字节流
   └ job     (作业)   二进制消息里承载 job 帧流(第 3 节)
```

- 两条连接都由台架拨出,主程序不主动连台架。
- 数据连接的 scheme 和主机取自台架配置的信令地址,路径固定是 `/bench/channel`,
  信令地址里的路径前缀不沿用。
- 凭证只在 HTTP 头里:`x-dhands-token`(台架配了 token 才带)、`x-dhands-csecret`
  (只在数据连接上)。任何帧里都没有凭证,所以帧可以整条写进日志。
  查询参数里的凭证一律不读。

## 2. 信令连接:控制帧

- 每个控制帧是一条 WebSocket **文本**消息,内容是一个 UTF-8 编码的 JSON 对象。
  接收方只按 JSON 解析,不依赖空白和键序。一条消息只放一个帧。
- 帧里必有 `verb`(帧类型),其余字段平铺在同一层。每种 verb 的字段见
  `schema/<verb>.json`,`schema/control.json` 是全部 11 种的合集。
- 帧里**没有** `v` 字段:版本是会话的属性,握手时定(sequences.md 第 2 节)。
- 收到意外内容时的统一规则:

| 收到 | 处理 |
|---|---|
| 帧里有不认识的字段 | 忽略这个字段 |
| 不认识的 `verb`,或这一方不该收到的 `verb`(例如台架收到 `hello`) | 回 `error`,码 `UNKNOWN_VERB`,会话继续 |
| 不是 JSON、是 JSON 但不是对象、缺必填字段、字段类型或取值不对 | 回 `error`,码 `BAD_FRAME`,会话继续 |
| 信令上的二进制消息 | 回 `error`,码 `BAD_FRAME`,会话继续 |
| 一个 `error` 帧本身有问题 | 只记日志,**不回** `error`(否则两边会互相回错误回不完) |

`error` 帧的 `re` 是出错那一帧的 `id`;那一帧不是对象、没有 `id` 或 `id` 不是
非负整数时不带 `re`。任何输入都不能让进程退出。握手阶段的例外见 sequences.md 第 2 节。

### 2.1 请求编号

主程序发的 `list_adb`、`list_com`、`restart_adb` 带 `id`(非负整数,同一会话里
唯一且递增);台架的回复 `adb_list`、`com_list` 带 `re`,等于请求的 `id`。
`open_channel` 不带 `id`,用 `cid` 对应。

### 2.2 单条消息的大小

信令上单条消息不超过 1 MiB。hello 里的操作表是最大的帧,现有台架远小于这个值。

## 3. job 通道:帧格式

与 v1 相同,没有改动。job 通道的数据连接上,两个方向的二进制 WebSocket 消息拼起来是
一条连续字节流,字节流被切成 job 帧。**帧边界和 WebSocket 消息边界无关**:接收方必须
自己缓冲、重组。

### 3.1 帧头

| 偏移 | 长度 | 字节序 | 字段 | 含义 |
|---|---|---|---|---|
| 0 | 1 | — | kind | `0x43`(ASCII `C`)= 控制帧;`0x44`(ASCII `D`)= 数据帧 |
| 1 | 4 | 大端,无符号 | length | payload 的字节数,0 ~ 8 388 608(8 MiB) |
| 5 | length | — | payload | C:UTF-8 编码的 JSON 对象;D:原始字节 |

### 3.2 接收规则

| 情况 | 处理 |
|---|---|
| 读帧头时连接干净结束(缓冲为空) | 正常结束 |
| 帧头或 payload 读到一半连接结束 | 错误 |
| kind 不是 C / D | 错误 |
| length > 8 MiB | 错误,不分配缓冲 |
| 该收控制帧时收到数据帧 | 错误 |
| C 帧 payload 不是 JSON 对象 | 错误 |

**发送方也要查 8 MiB 上限**:payload 超过上限的帧不发,改成报错。v1 里只有主程序查。

### 3.3 控制帧的 JSON 部分

- 主程序 → 台架:作业请求,只有一个,是通道上的第一帧(`schema/job-request.json`)。
- 台架 → 主程序:事件,`ev` 只有 `accepted`、`progress`、`file`、`done` 四种
  (`schema/job-event.json`)。这是固定集合:收到别的 `ev`,接收方按通道出错处理。
- `progress` 的 `phase` 是开放的字符串,由操作自己定;不认识的阶段按普通进度显示。
- `done` 失败时 `code` 必须非空;`error` 文本超过 4096 个字符时发送方截断。

### 3.4 数据帧

- 只有主程序发,只在 image 类操作(`OpDesc.image = true`)的请求帧之后发。
- 主程序每块不超过 64 KiB,最后发一个 **length = 0 的 D 帧**表示镜像发完。
- 台架按请求里的 `size` 收:收满 `size` 字节就停止读;先收到 0 长度 D 帧就提前结束接收,
  再按大小和 sha256 判定。

### 3.5 样例字节

`frames/binary/job-frames.json` 里有逐字节的样例,两端的编码器和读取器都对它测。

## 4. tcp 和 serial 通道:原始字节流

- 两个方向都是 WebSocket **二进制**消息,内容就是要转发的字节,没有帧头。
- 发送方每次最多发 64 KiB。接收方不依赖这个大小。
- tcp 通道:`open_channel` 的 `target` 只能是 `127.0.0.1:5037`,它的意思是「台架本机的
  adb server」。台架自己再查一遍,然后连本机 `127.0.0.1:<配置的 adb 端口>`(默认 5037)。
- serial 通道:一端是台架上打开的串口。`com` 是串口名,或者 `loop://`(pyserial 的
  回环口:写进去的字节原样读回来,用来在没有串口的机器上检查通道本身)。其他 URL 一律拒绝:
  `socket://` 一类会让台架替主程序去连任意网络地址。

## 5. 数据连接上的文本消息和空消息

**发送方不得在数据连接上发文本消息,也不得发 0 字节的二进制消息。**
接收方收到任何一种,都当作这条数据连接结束,关掉它。v1 里两边对这两种消息的处理不同
(known-gaps G15),v2 统一成这一条。

## 6. WebSocket 层的其他参数

| 项 | 规定 |
|---|---|
| 压缩(permessage-deflate) | 可以协商,也可以不开;两端都必须能在不压缩时工作 |
| 数据连接单条消息上限 | 接收方不设上限(job 帧自己有 8 MiB 上限) |
| ping / pong | 由 WebSocket 库处理;协议层的存活检测靠 heartbeat(sequences.md 第 3 节) |

## 7. 参数规则的正则子集

操作表里 `text` 和 `partition` 参数带 `pattern`。两端都会执行它,而两端不是同一种语言,
所以 `pattern` 只能用 Python `re`、ECMA-262、Rust `regex` 读出来意思一样的写法:

| 能用 | 写法 |
|---|---|
| 字面字符 | 可打印 ASCII(空格到 `~`);元字符 `. ^ $ \| ? * + ( ) [ ] { } \` 要写成 `\` 加它本身 |
| 十六进制字符 | `\xHH`,正好两位 |
| 预定义类 | `\d` `\D` `\w` `\W` `\s` `\S`,**只指 ASCII**:`\d` = `[0-9]`,`\w` = `[A-Za-z0-9_]`,`\s` = 空格、`\t` `\n` `\v` `\f` `\r` |
| 字符类 | `[...]`、`[^...]`,里面可以有范围 `a-z`、`\xHH`、预定义类;`-` 放在开头或结尾是字面字符;`]` `[` `\` `^` 要转义 |
| 量词 | `*` `+` `?` `{n}` `{n,}` `{n,m}` |
| 分组 | `(...)`、`(?:...)`,以及 `\|` |

不能用:`.`(三种语言里它匹配的字符不同)、`^` `$` `\A` `\Z` `\z` `\b` 等锚点、前后查找、
反向引用、命名分组、内联标志、懒惰或占有量词、`\n` `\t` `\u` 一类转义(写成 `\xHH`)、
非 ASCII 字面字符(写成字符类或 `\xHH`)、字符类里的 `&&` `--` `~~`(Rust 里是集合运算)。

**匹配永远是整串匹配**,`pattern` 两端不写锚点:

| 语言 | 怎么执行 |
|---|---|
| Python | `re.fullmatch(pattern, value, re.ASCII)` |
| ECMA-262 | `new RegExp("^(?:" + pattern + ")$")`,不加 `m` 标志;`\d\w\s` 换成上表的 ASCII 类 |
| Rust `regex` | `Regex::new(&format!("^(?:{pattern})$"))`,`\d\w\s` 换成上表的 ASCII 类(或在 `(?-u:...)` 里写) |

长度(`max_len`)和量词都按 Unicode 码点计数。

读到操作表时,`pattern` 不在子集里的,按坏帧处理(sequences.md 第 2 节)。
`patterns.json` 里有三组样例:子集内的写法、子集外必须拒绝的写法、(规则,输入,应不应该通过)。
两个实现都要全部通过。
